Gated PixelCNN, one pixel at a time

A PixelCNN models an image as a product of per-pixel conditionals in raster order, p(x | y) = ∏i p(xi | x1, …, xi−1, y), each computed by masked convolutions. This page reproduces the three ideas of Conditional Image Generation with PixelCNN Decoders (van den Oord et al., NeurIPS 2016) with a small model trained on binarized MNIST, running in your browser.

Things to try

  • Blind spot. Hover a pixel near the middle of the grid with PixelCNN selected and drag the layers slider up. The receptive field grows along a diagonal, and the red pixels above and to the right of it never join, however many layers you add. Switch to Gated PixelCNN: the vertical stack covers everything above, the horizontal stack covers the row to the left, and the red is gone.
  • Sampling. Pick a digit and press Sample. Each pixel needs its own pass through the network, because it depends on the pixels just drawn: 784 passes, one after another. The bar shows the model's p(xi = 1) for the pixel being drawn. It is near 0 or 1 inside strokes and background, and uncertain at edges.
  • The class y enters every layer as a learned bias inside both gates. Press All digits to see one model follow ten different conditions. Choose none for unconditional samples from the same network.
  • Lower the temperature for cleaner, more typical digits. Raise it for noisier, more varied ones.
  • Inpainting. Keep the top half of a test digit and complete it, a few times. The completions vary but continue the strokes. Try conditioning on another class to see how far the model will bend the top half. Then switch to keep bottom half. The top now comes first in raster order, so it is generated without any knowledge of the bottom, and the halves rarely fit. The −log p of the kept half shows it.

Differences from the paper: pixels are binary, so each conditional is one Bernoulli logit instead of a 256-way softmax, and there is one channel, so no R→G→B ordering inside a pixel. The class enters as a one-hot vector, one learned bias per class and gate (paper eq. 4). The browser evaluates the network incrementally. Each row of the vertical stack is computed once, and each pixel needs one horizontal-stack step, so it never repeats work. The result is exactly what 784 full forward passes would give.
